# Broker cheat sheet

The app stores broker notes separately from the generated itinerary in each immutable CARR sheet revision. Regeneration reads current accepted route facts, preserves notes and appends through the existing autosave contract. History is read-only and displays the latest 100 revisions.

The model checks session retirement during editing, saving, conflict recovery, regeneration and history viewing. It does not model network scheduling, database isolation, note text or fact values. Browser acceptance tests cover those values and verify that writes target only the sheet endpoint.

To regenerate, copy broker-sheet.mmd, BrokerSheet.tla, BrokerSheet.cfg and BrokerSheet.map.mjs into a scratch directory and run the installed statechart skill's `statechart.mjs from-chart` command with `--module BrokerSheet --png`. Set TLA2TOOLS to the installed tla2tools.jar. The accompanying summary and stories record the executed model result.

The two interface candidates were a single generated text document and separate notes plus generated facts. Separate fields preserve notes without unreliable text merging. The existing versioned save, replay and conflict machinery remains the only write path.

The mapping file is generated by the third-party statechart skill and loaded by its wrapper. It is registered as a tool entry in Knip and an inventoried generated artifact in the TypeScript migration scope.

A failed regeneration returns the same authorized dirty draft to editing and resumes its autosave. Browser regressions cover this transition with three persisted saves and retained notes after reload, retirement during both regeneration and history reads (late success and failure), and history failure/retry without replacing edits. The History region includes Reading, success, failure and retirement.
