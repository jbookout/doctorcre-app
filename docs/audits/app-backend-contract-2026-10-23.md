# App ↔ CARR backend contract audit — 2026-10-23

**Report only. No application or backend implementation changes.** The MCP machinery purge did **not** remove an app-used verb: all **95 distinct MCP verb names in the runtime adapters** (42 reads, 53 writes, including two methods without a current UI caller) exist in the audited tool definitions and generated registry; none is in the 60-name retired list. ### S1 — Invalidate the whole view when its authenticated session changes

**F01 — P1, M–L. Private Doc Chats remain visible after denied pagination.** A successful first page followed by a 401/403 on “Load more” preserves `rows: held` (A `js/conversations.js:493`, `:509`); rendering still paints every title and visibility regardless of the refused state (`:206`, `:228`). B `mcp-server/src/doc-conversation.js:320` limits the list to owned/granted/unrevoked conversations, and `:93` returns private titles. B `mcp-server/src/dealroom-web.js:1100` explicitly refuses missing sessions with 401. This is a demonstrated client retention defect after denial; it does not mean the backend returned another actor's records.

The same incomplete invalidation affects the primary Local Deals board (A `js/pipeline.js:1358`, `:354`, `:291`; its detail drawer clears, but the board does not), National Accounts (A `js/board-sync.mjs:390`, `:523`; `js/app.js:224`), Doc Activity (`js/doc-activity.js:63`, `:90`), Work Requests (`js/system-work-app.js:21`, `:60`, `:196`) and Control Room queue (`js/control-room.js:174`, `:209`). The queue additionally suppresses its failure notice after any page has loaded. Account identity refresh silently retains its old result on failure (`js/app-shell.js:109`). Tour editor detects a changed session binding but clears only selected composer state, leaving the current tour, cheat sheet, feedback, property cache and share URL (`tours/app.js:10`, `:33`); B `mcp-server/src/tour-internal-web.js:361` supplies that binding for a reason. Some later Control Room reads lack the generation check used by its main `take` function (A `js/control-room.js:131`, `:216`, `:223`, `:243`).

**Concrete fix:** connect the existing page controllers to one verified session generation. On explicit 401/403 or changed principal/session, abort pending reads, advance generations, clear private rows/details/forms/Doc context and actor labels, disable writes and require a new bootstrap. Bind pending mutations to their original actor/session, retaining them only in a separately scoped recovery state. On a same-session network outage, keep data only with a visible last-success timestamp and stale notice. Reuse the stronger patterns in A `js/leads-workspace-app.js:148`, `js/workspace-business.js:703` and `tours/planner.js:34`.

**Ship gate:** first-page success → denied pagination clears private titles; old in-flight success cannot repaint after newer denial; partner switch with an open editor clears prior content and prevents submission under the new actor. Network-only failures remain visibly distinct from sign-out. A synthetic board probe already confirms a 401 currently leaves the prior record with status `reconnecting`.

**F07 — P2, M. Personal/local state is not consistently revoked or actor-scoped.** Saved Search names/query text live in the global `doctorcre.saved-views.v1` key (A `js/search-model.js:516`, `:524`), load before authenticated results (`js/search.js:333`) and survive signout (`js/app-shell.js:131`). A synthetic new-reader check retrieves the prior saved query with no actor argument. This can disclose a prior user's search intentions even where client records are intentionally shared. B `mcp-server/src/dealroom-web.js:1100`, `:1117` requires a current actor for server reads; that control does not cover these local strings. Tour Day scopes IndexedDB records, but its local signout event/sessionStorage mechanism does not revoke another tab's saved scope (A `js/offline-tour-session.js:1`; `tours/day.js:244`; backend session revocation B `mcp-server/src/dealroom-web.js:475`). The offline/cross-tab exposure is conditional on an already authorized tab and retained local copies; no unauthorized server fetch is asserted.

**Concrete fix:** scope Search by a verified actor, discard rather than adopt the legacy unscoped key, and clear in-memory views on invalidation. Broadcast revocation across tabs and service workers; persist a minimal revocation/session epoch that every offline restore checks before opening scoped records. Keep privacy policy for offline capture retention explicit. **Ship gate:** partner A saves query/capture; logout in another tab; partner B or offline reload cannot restore A's private state.

**F08 — P2, S, conditional. Generic shell caching includes `/auth/session`.** A `public-shell/sw.js:8` excludes `/api/` and MCP but not `/auth/`; `:56` caches every successful GET without consulting `Cache-Control` and replays it on network loss. B `mcp-server/src/dealroom-web.js:1117` serves actor and session/CSRF metadata from `:741`, despite `no-store` at `:73`, `:129`. A synthetic service-worker check confirms a successful `no-store` session response is cached and returned offline.

**Reachability limit:** the normal A `js/app-shell.js:128` call verifies logout and expects 401, which is not cached. Exposure needs a previous successful authenticated read/navigation of that endpoint or a reauthentication race; a routine logout alone does not populate it. **Concrete fix:** cache only allowed static shell assets, always bypass `/auth/*` and `no-store` responses, and delete older caches on upgrade/logout. **Ship gate:** synthetic auth responses never enter CacheStorage and cannot be replayed offline.

**F11 — P2, M, conditional. Public share tabs are not bound to their originally opened projection.** B `mcp-server/src/reports-web.js:13`, `:76`, `:158` uses one host-wide share-session cookie; report/map/feedback reads derive their target from it (`:182`). A `reports/share.js:235` sends no per-tab projection identity, while the original bearer fragment is scrubbed (`reports/share-bootstrap.js:16`; `reports/share.js:319`). Opening authorized link A and then authorized link B in another tab can make a token-less reload of tab A display B. Independent parallel packet/map reads (`reports/share.js:280`) lack a common identity comparison. This is wrong-share context in a shared browser, not arbitrary unauthorized access; possession of a valid link remains required, and feedback writes do include explicit projection/property references.

**Concrete fix:** bind the page to an opaque projection reference per tab and verify it against the share session on every read, or isolate share sessions by route. On mismatch clear the view and require that specific link to be reopened; continue removing raw bearer material after exchange. **Ship gate:** two simultaneous links, refresh/retry and mixed delayed responses cannot paint one link's projection under the other's tab context.

### S2 — Preserve write identity and make concurrency explicit

**F02 — P1, L across several small PRs. Retrying an uncertain write can lose its receipt or repeat an effect.** Room wire/queue POSTs send only `{body}` (A `js/progress-wire.js:837`, `:1886`; `js/queue.js:62`) and the wire says the turn did not reach the server. B `mcp-server/src/dealroom-web.js:617` derives its message id from session, text and a one-minute bucket, and `:660` appends with that id. A lost reply followed by retry across a minute boundary produces a different id; even retries seconds apart can duplicate a work command. No `base_version` is needed for an append, but the request identity must survive uncertainty.

Other paths create a new key on the next attempt: national account/market/owner forms and review/confirmation clicks (A `js/app.js:1031`, `:1069`, `:1080`, `:1088`, `:1137`, `:1175`, `:1186`, `:1230`), non-report Work Request forms (`js/system-work-client.js:49`, `:89`), event forms when reopened (`js/ideas.js:314`, `:324`, `:348`; fallback key `js/live-client.js:74`), Model Room answers (`js/model-room.js:692`, `:708`) and call candidate approval (`js/call-mode.js:496`, `:521`). B `mcp-server/src/tools.js:299` and `mcp-server/src/work-request-intake.js:695`, `:938` replay by key/material; a new key cannot recover the old receipt. Version checks prevent some duplicate transitions, so loss of receipt recovery is broader than guaranteed duplicate writes. A synthetic repeated plan submission confirms the app generates different keys.

**Concrete fix:** use the existing command-operation model to retain exact key/body/actor before the first send; disable material changes while unresolved; replay/reconcile the same intent and create a new key only for a new reviewed action. Preserve HTTP/auth status and distinguish “refused” from “outcome unknown.” Keep the already-correct retained report/new-deal/Model Room turn patterns. The HTTP room endpoint needs a coordinated producer change accepting a caller-generated UUID scoped by the server to actor/session and payload; adding an ignored field only in the app will not fix it. **Ship gate:** committed write/lost reply/retry returns the original receipt, including across the room minute boundary; definitive refusal permits a new reviewed intent; actor change cannot retarget an old operation.

**F05 — P2, M. The blanket fresh `base_version` requirement is not met.** All 53 direct MCP write schemas name `idempotency_key`; only 24 name `base_version`/`base_versions`. Versionless creates, appends and presence leases are legitimate exceptions. Field patches instead carry `base_event_id`, and undo/conflict resolution validate the latest field event (B `mcp-server/src/tools.js:9731`, `:9763`). Those are concurrency checks, not missing-version defects.

However, next-step/date, market-agent and national-owner replacement have no expected prior state (A `js/app.js:958`, `:1031`, `:1088`; B `mcp-server/src/tools.js:9471`, `:2290`, `:9583`, `:9594`, `:9613`, `:9622`). Newest-wins can replace a newer partner edit. Many otherwise versioned forms use a valid but previously rendered read: Leads, invoices, preferences, board answers, vendor edits, event edits and Work Request forms; the inventory identifies each. Existing CAS correctly refuses stale versions, but an immediate fresh-read requirement is not satisfied by those paths.

**Concrete fix:** add a supported expected version/event to the three replacement contracts and return it from their reads, then reread/review before creating a new write intent. For existing CAS forms, fetch the current record when opening/submitting the review and keep the user's reviewed version attached; if it changed, show the difference instead of silently rebasing. Never refresh the version of an unresolved retry. Do not blindly add `base_version` to schemas that do not accept it: B `mcp-server/src/mutation-registry.js:38` rejects extra top-level fields. **Ship gate:** two-partner concurrent edits conflict visibly without overwriting; receipt retries retain their original version/key. Dynamic triage already rereads its exact row and retains the prepared request (A `js/system-work-board-model.js:29`, `:43`, `:46`).

**F10 — P2, M. Tour cheat-sheet conflict recovery can trap a dirty draft on a stale revision.** A `tours/app.js:734` submits the displayed revision with a newly generated key. Its catch discards the status (`:795`); automatic refresh skips dirty detail (`:883`). B `mcp-server/src/tour-internal-web.js:209` requires `expected_revision_number`, and `:284` maps stale revision errors to HTTP 409. Retrying without rereading repeats the old revision. Related route/projection/PDF actions also mint new keys per invocation (A `tours/app.js:728`, `:872`, `:880`), covered by F02. JSON scalar/array text is another concrete request mismatch: A `tours/app.js:733` passes any successfully parsed JSON as `content`, whereas B `mcp-server/src/tour-internal-web.js:209` requires an object.

**Concrete fix:** retain the draft and original operation key; on a definitive conflict, reread the current sheet, render the difference and require deliberate resubmission against the reviewed version. Validate a parsed sheet as an object, with a useful error for scalar/array input. Do not silently replace the version of an unresolved write. Reuse the current route composer's reconciliation pattern. **Ship gate:** lost reply replays the same operation; concurrent save preserves the draft and presents current state; scalar/array JSON is rejected visibly before send.

### S3 — Repair national-account request construction before re-enabling success claims

**F03 — P1, M. “Create national account” always omits a required object.** A `js/app.js:1065`–`:1069` sends name/owner/vertical/key only; B `mcp-server/src/tools.js:9639` requires `research_evidence`, and `:843`, `:9054` enforces required arguments before handler execution. New market transactions have a second branch-specific failure: A `js/app.js:1080` omits research evidence; B `mcp-server/src/tools.js:9694` requires it when creating a previously unknown sub-client. Existing sub-client reuse can still work.

The same form ignores a returned `needs_confirm` object and would show “created” (A `js/app.js:1069`; B `mcp-server/src/tools.js:9643`). **This is latent today for this form** because missing required research evidence fails earlier; fixing the request must include this confirmation branch. Market assignment also sends `market:null` for a blank field (A `js/app.js:1031`) against B `mcp-server/src/tools.js:9586`'s string schema. The current coercer skips null (`:890`) and handler tolerates it (`:9602`), so this is published-schema drift, not a proven runtime rejection.

**Concrete fix:** collect/resolve genuine research evidence using the producer's existing evidence schema, or restrict the form to linking already researched entities; do not fabricate evidence. Separate existing-subclient and new-subclient requests, validate response receipts, and show candidate confirmation before a deliberate `force_new` request. Omit optional blank market or amend producer nullability intentionally. Retain request keys as in S2. **Ship gate:** exact request-schema checks for new/reused account paths, missing evidence visibly actionable, duplicate candidate neither creates nor claims success until confirmed.

### S4 — Make every screen failure distinguishable from no data

**F04 — P1/P2, M. Some user actions reject without a recovery state.** National agenda start/review/end and confirmation clicks await mutations outside a catch (A `js/app.js:1134`, `:1169`, `:1183`, `:1230`, `:1252`). Their producer verbs are present (B `mcp-server/src/tools.js:9488`, `:9522`, `:9553`, `:9822`), but transport/auth failure can leave controls unchanged and create an unhandled rejection. Tour list buttons invoke `void loadTour(...)` (A `tours/app.js:126`); `loadTour` (`:704`) has only `finally`, leaving “Loading tour…” and old details after failure. B `mcp-server/src/tour-internal-web.js:278`, `:330` documents HTTP auth/validation/conflict/unavailable failures; B `dealroom-web.js:1108` supplies session refusal.

**Concrete fix:** route every action/detail read through visible pending/success/refused/unknown states, catch event-handler promises, hide old selection on denied access, and preserve an exact write intent until reconciliation. A timeout must end a spinner without claiming a write failed. **Ship gate:** injected 401, 403, timeout, network rejection, malformed response and producer refusal each stop loading and expose sign-in, retry or reconciliation without an unhandled rejection.

**F06 — P2, S–M. Secondary read failures look like absent information.** A `js/correspondence.js:14` catches errors/timeouts into null and `:10` renders only nonempty ready groups; both an empty result and an unavailable/unauthorized thread render `''`. B `mcp-server/src/governed-correspondence-store.v5.js:241`, `:273`, `:295` explicitly distinguishes readiness/thread unavailability. A synthetic 401 produces an unavailable model and zero rendered characters. Search catch-up similarly swallows all failures then marks the combined search ready (A `js/search.js:213`; B `mcp-server/src/tools.js:3217`, auth at `dealroom-web.js:1108`). Optional client/vendor context strips status and omits failed sections (A `js/live-client.js:227`; `js/pipeline-model.js:435`, `:449`), despite B `dealroom-web.js:987`'s distinct error responses. Capture queue logs failures only (A `js/app.js:305`; B `tools.js:3604`).

**Concrete fix:** model each secondary section independently as loading/ready/empty/unavailable, render a compact failure+retry state, and propagate explicit authorization failure to S1. Preserve successful sibling sections for ordinary network failures. Add “No linked evidence” only for a confirmed empty read; do not manufacture it from exceptions. **Ship gate:** empty and 503 look different; 401 clears protected state; an optional section cannot fail silently. Operational screens that already render generic failure should preserve status and add a sign-in action rather than growing another error system.

**F12 — P2, S. Local Call Mode has no deadline for normal helper requests.** Only eligibility has a timeout; ordinary start/stop/state and post-call context/report/sync/draft calls do not (A `js/call-mode.js:152`, `:200`, `:594`, `:630`; `js/post-call-client.js:22`). Rejections render errors, but a hung request can leave disabled controls indefinitely. B `tools/dictation-rig/bin/call-mode.py:473` invokes local processing, and `tools/dictation-rig/bin/post_call.py:939` can wait on an external draft creator. These are local companion operations, not CARR cloud authentication.

**Concrete fix:** add bounded request deadlines and an explicit unknown-outcome state; read local state/report before retrying start/stop/draft. Preserve existing content-hash draft deduplication (B `tools/dictation-rig/bin/post_call.py:921`). **Ship gate:** a never-settling mock ends its spinner; timeout does not claim a write definitely failed; recovery does not create a duplicate draft.

### S5 — Remove or replace the unsupported diagnostic integration

**F09 — P2, S to remove / M for a paired supported replacement.** A browser sends POST `/api/v1/runtime-errors` and ignores non-2xx (A `js/error-tracking.js:67`); the edge forwards it and invokes `CARR_ERRORS.capture` (`src/worker.js:226`, `:240`) via `RuntimeErrorSink` (`wrangler.jsonc:14`, `:24`). A bounded source-wide JS/MJS search found neither integration in this pinned backend.

**Concrete fix:** remove the obsolete sink/binding or deliver a small explicitly supported diagnostic successor in CARR and then repoint the app. Verify route/export compatibility against the exact producer revision. Give operators a bounded diagnostic-delivery indicator that cannot recursively report itself. Best-effort telemetry does not need a record `base_version`; no current producer request schema can be certified for an absent endpoint. **Ship gate:** missing/404 sink is detected by contract checks; supported ingestion receives synthetic scrubbed errors; app remains usable when it fails. Actual deployed ingestion and deployment compatibility were not exercised, so the missing export is a source compatibility risk, not a claim that production is down.
